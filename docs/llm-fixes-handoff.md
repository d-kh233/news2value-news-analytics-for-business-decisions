# Правки в llm/ и agent/ из ветки feat/llm-fixes-daria (для ML-команды)

Обновлено 25.10.2026. Ветка `feat/llm-fixes-daria` отходит от `test-backend` (1df37eb). В ней бэкенд временно взял на себя часть ML-работы, чтобы не ждать: дайджест, ответ на вопрос, разметку новостей по отраслям и «0 карточек без объяснения». Обычно бэкенд `llm/` и `agent/` не трогает. Здесь правки сделаны осознанно, и каждая помечена в коде комментарием `# ПРАВКА feat/llm-fixes-daria: <что и зачем>`. Их можно найти так:

```bash
git grep -n "ПРАВКА feat/llm-fixes-daria" -- llm agent
```

В тексты промптов (`llm/prompts/*.md`) маркер не ставился, иначе он ушёл бы в модель. Новые промпты перечислены ниже и в docstring модулей, которые их загружают.

**Что не проверено.** Ключа LLM у бэкенда нет, `replay_cache/llm/` пуст. Поэтому `generate_digest` и `answer_question` проверены только на подменённой модели (тесты с поддельным `complete`) и на запасном пути `LLM_MODE=stub`. Ни одного вызова настоящей модели не было, качество промптов `digest@v0` и `qa@v0` на живой модели неизвестно. Нужен прогон `LLM_MODE=live` (см. «Как проверить»).

### Как бэкенд это вызывает

```
GET /companies/{id}/digest  → services/insight_service.get_digest
    → ml_ports/digest_port.digest_summary (под кэшем llm_cache)
        ML_MODE=fake → склейка заголовков (заглушка бэкенда)
        ML_MODE=real → llm.digest.generate_digest(..., complete=Gateway(Settings.from_env()).complete)
                       модель недоступна (LLMUnavailable / LLMCallError) → та же склейка, в кэш не кладётся

POST /insights/{id}/ask → задача jobs(kind=ask) → worker → services/qa_service.run_question
    → ml_ports/qa_port.answer_question (под кэшем llm_cache)
        ML_MODE=fake → ответ-шаблон + все источники инсайта
        ML_MODE=real → llm.qa.answer_question(...) + llm.qa.answer_sources(...); недоступна → шаблон
```

Шлюз модели — тот же `agent.gateway.Gateway`, что у карточек: `LLM_MODE=stub|live|replay`, дневной лимит, запись ответов в `replay_cache/llm/calls/`. Обвязка — `backend/app/ml_ports/llm_call.py`. Модель — `MODELS["fast"]` (Gemma): задача — сжать готовый текст. Есть и вторая причина: на GLM без отключения рассуждений бывают пустые ответы, это чинит коммит `782fc0b` в ветке `demo-cache`, пока не слитый.

### Детали generate_digest

- На вход: до 10 карточек в формате бэкенда (самые важные первыми), строка профиля компании (`company_facts` из `llm/insight.py`), период `day|week`.
- Модели передаются тип, важность, `title`, `summary`, `impact_on_company` каждой карточки и признаки компании `F:`/`G:`.
- **Отступление от названия поля:** `DigestItem.news_id` содержит не id новости, а `I:<id инсайта>`, ровно как в квадратных скобках промпта. Так проще проверять ответ и связывать пункт с карточкой. Если ML-команде нужен именно id новости, поменяйте `digest_item_id()` и проверку `check_items`, бэкенд `items` не читает.
- Проверка в цикле исправления: один пункт на каждый инсайт, без чужих и повторных id, непустой `overview`.
- Бэкенд отдаёт `summary = f"{title}. {overview}"`. Порядок `insight_ids` задаёт бэкенд (по важности), а не модель.

### Детали answer_question

- На вход: карточка (с `details`, если её сделал агент; у моков и заглушки `details` нет), вопрос, история `[{question, answer}]` (последние 5 пар того же пользователя по этому инсайту).
- Допустимые id: источники карточки (`sources[].id`; у старых карточек без id — `S:1`, `S:2`…), id из `details` и признаки компании.
- Проверка в цикле исправления: непустой `answer`, все `statements[].source_ids` из допустимых.
- `answer_sources` возвращает источники карточки, на которые сослались утверждения; ссылок нет — все источники; `out_of_scope` — пусто.
- `suggested_questions` бэкенд пока не сохраняет: в таблице вопросов для них нет поля.

## 2. Можно менять спокойно и что требует синхронизации

**Можно спокойно доработать или заменить своей версией:**
- тексты `llm/prompts/digest.system.md` и `llm/prompts/qa.system.md` (поднимите `PROMPT_VERSION`, тогда кэш бэкенда сбросится сам);
- внутренности `llm/digest.py` и `llm/qa.py` при той же сигнатуре и том же возвращаемом типе (`Digest`, `ChatAnswer`);
- словари `SYNONYMS` и `_NAME_STOP`, пороги в `llm/okved/tagging.py` (поднимите `TAGGER_VERSION`; затем `uv run python scripts/tag_documents.py` переразметит базу);
- словари и правила в `agent/heuristic_extract.py`, его можно и удалить совсем, если модель будет размечать всё (уберите вызов `_extract_heuristic` в `orchestrator.run`);
- текст `_empty_note`.

**Лучше не трогать без синхронизации с бэкендом:**
- сигнатуры `generate_digest`, `answer_question`, `answer_sources`, `source_index`, `industry_tags`, `merge_tags`: их вызывают `ml_ports`;
- формат тегов `okved:NN` (две цифры, с нулём впереди): по нему работает фильтр ленты `industry` и `GET /documents`;
- `"id"` в `sources[]` в `backend_adapter.to_backend_insight`: по нему бэкенд связывает источник карточки с документом;
- ключ `COUNTERPARTIES` в строке профиля (`[{id: "P:U_3", direction, okved_name}]`), его кладёт `backend/app/ml_ports/agent_port.row_from_db`;
- правки в `agent/orchestrator.py`: ветка `feat/agent` меняется часто, при слиянии возможен конфликт. Правки небольшие и помечены маркером, их проще перенести руками, чем сливать вслепую.

## 3. Разметка новостей по отраслям (`llm/okved/tagging.py`)

**Алгоритм:**
1. Для каждой из 88 отраслей карты `okved_sensitivity.csv` строится набор корней:
   - корни слов из названия отрасли (слово ≥ 5 букв, корень = слово без 2 последних букв, но не короче 5); общие слова («производство», «прочие», «услуги», «право», «финансовые»…) отбрасываются;
   - ручные синонимы `SYNONYMS` для отраслей, которые встречаются в новостях («застройщ», «ипотек» → 41; «аэропорт», «авиа» → 51; «топлив», «азс» → 19…).
2. Корень совпадает с началом слова. Корни до 3 букв и корни с `$` на конце («кафе$», «руда$») — только целым словом, иначе «газ» совпал бы с «газетой», а «кафе» — с «кафедрой». Корень из нескольких слов («торговых сет») — слова подряд.
3. Корни одной отрасли схлопываются: из «автомобил» и «автомобилей» остаётся один, чтобы одно слово не давало двойной вес.
4. Вес: корень в заголовке — 2, только в начале текста (первые 1500 символов) — 1. Тег ставится при весе ≥ 2, не больше 3 отраслей на новость.
5. Существующие теги источника (`general`, `economy`, `bank_analytics`, рубрики RSS) не трогаются; `okved:*` пересчитываются целиком.

**Где вызывается:** при сборе каждого документа (`backend/app/ingestion/runner.py`) и для уже собранных — `scripts/tag_documents.py` (этот же шаг есть в `scripts/seed_demo.py`).

**Результат на реальных данных (25.10):** отрасль получили 32 новости из 80. Проверены вручную 23 из первых 60: ипотека и риелторы → 41/68, аэропорты → 51, топливо → 19/06, подстанции → 35, ПВЗ → 47/68, кредиты наличными → 64, аграрии → 01. Новости про ставку ЦБ и инфляцию отрасли не получают, и это правильно: они касаются всех.

**Ограничения:**
- Это не понимание смысла. Новость «студенты столкнулись со спецназом» получает 85 (образование), «подстанция повреждена после атаки БПЛА» — 35 (электроэнергетика). В отбор агента такие новости не проходят, их режет признак шума (раздел 4), но тег у документа остаётся.
- Слово «банк» намеренно не в словаре: «Банк России» есть почти в каждой экономической новости.
- Отрасли, о которых в словаре мало синонимов, будут находиться редко.
- Тег не знает направления (хорошо или плохо для отрасли), это только «о ком новость».

## 4. «0 карточек без объяснения» при ML_MODE=real + NEWS_SOURCE=db

**Было:** новости из `documents` приходят без разметки. В `LLM_MODE=stub` (и при промахе replay) `_extract_missing` их пропускал, `score_news` давал 0 всем, прогон возвращал 0 карточек, а в `pipeline_runs` было `empty` с короткой фразой.

**Выбранный вариант — мягкая разметка внутри агента**, а не замена агента заглушкой бэкенда.
- Почему: карточка остаётся карточкой агента (его скоринг, тезисы банка, трейс, критик в live), в одной ленте не смешиваются два генератора, причина видна в трейсе.
- Замена на `ML_MODE=fake` оставлена только как подстраховка в `scripts/seed_demo.py --mode auto`, и там видно, что сработала она.

**Как работает `agent/heuristic_extract.py`:**
- вызывается шагом «Разметка по ключевым словам» (tool `heuristic_extract`, статус `fallback`) **только** для новостей, у которых после `_extract_missing` нет `event`: stub, промах replay, ошибка модели, сверх лимита 20;
- `okved_hints` берутся из `industry_tags` (раздел 3);
- `factor_moves` — по словарю `FACTOR_ROOTS` (ставка, курс, нефть и газ, металлы, агро, золото, инфляция, спрос, рынок труда, санкции и ВЭД), сила `low`;
- направление ставится, только если фактор и слово-направление стоят в заголовке или первой фразе: «сохранил», «пауза» → `unchanged`; «вырос», «ускорился» → `up`; «снизил», «замедлился», «дезинфляция» → `down`; иначе `uncertain`;
- `event_type` выводится из факторов (ставка → `monetary_policy`, инфляция → `inflation` …), затем «санкц»/пошлины → `sanctions`/`trade`, законы и налоги → `regulation`, есть отрасль → `industry`, иначе `other`;
- происшествия (`NOISE_ROOTS`: погиб, БПЛА, атака, протест, подтоп…) в заголовке без макрофакторов → `is_noise = true`;
- в разметке `model = "rules"`, `prompt_version = "heuristic_extract@v0"`, `quality_flags = ["ambiguous"]`.

**Если и после этого ничего не прошло порог,** у шага «Скоринг и отбор» статус `skipped` и заметка с числами:
`ни одна новость не прошла порог релевантности 0.5: новостей 3, размечено моделью 0, по ключевым словам 3, без разметки 0, шум 1; лучший скор 0.31`.
Бэкенд кладёт её в `pipeline_runs.error` (статус `empty`). Её же видно в `GET /jobs/{id}/run`, а при `GET /jobs/{id}` задача `done`.

**Результат на демо (LLM_MODE=stub, NEWS_SOURCE=db, 25.10):** по 3–4 карточки на компанию. Пример для девелопера U_67064: «Минфин связал повышенную ключевую ставку…» → risk, «Аксаков: основной потенциал снижения ключевой ставки…» → opportunity, «Набиуллина выступила против увеличения льготной ипотеки» → событие отрасли 41.

**Ограничения:** у большинства новостей направление `uncertain`, поэтому тип карточки чаще `event`; макровлияние слабее, чем после разметки моделью. Карточка в stub собирается по правилам (`agent/rules.py`) с `confidence = low`. Настоящая разметка — `extract_event` в live/replay, этот модуль только не даёт ленте молча опустеть.

## 5. Семь расхождений из B5 (`docs/ml-integration-notes.md`)

| # | Расхождение | Статус |
|---|---|---|
| 1 | Настоящие новости не размечены, в stub/replay лента пустая | **Частично закрыто:** разделы 3–4. Полная разметка моделью по-прежнему требует прогона `LLM_MODE=live` и коммита `replay_cache/` (решение о публикации кэша за тимлидом) |
| 2 | У источников в карточке нет id документа | **Закрыто:** `backend_adapter` кладёт `"id": sid` в `sources[]`; бэкенд по нему обновляет источник данными документа (`GET /insights/{id}`) |
| 3 | Нет значения `generated_by` для заглушки | **Ограничение прототипа.** Схему `Insight` менять нельзя: в `payload` `rules`, в колонке `insights.generated_by` — `fake` |
| 4 | Разные «сегодня» у агента и бэкенда | **Закрыто:** агент берёт дату по UTC (`datetime.now(timezone.utc).date()`), как `news_provider`. `AGENT_TODAY` по-прежнему главнее |
| 5 | Окно поиска расширяется само | **Сделано видимым:** у шага «Поиск новостей» с расширенным окном статус `fallback` и заметка «за 1 дн. новостей нет — окно расширено до 4 дн.». Само поведение (удвоение до 90 дней) не меняли: это решение тимлида |
| 6 | У тезисов банка нет URL | **Ограничение прототипа.** Настоящих ссылок на материалы банка нет, выдумывать их нельзя; `sources[].url` у аналитики банка — `""` |
| 7 | Контрагенты из платежей не доходят до агента | **Закрыто без смены сигнатур:** `agent_port.row_from_db` кладёт в строку профиля `COUNTERPARTIES` (до 5 покупателей и 5 поставщиков: `P:<id>`, направление, отрасль), `agent/generator.counterparties_of` передаёт их в существующий параметр `counterparties` у `interpret` / `interpret_reviewed`, модель может ссылаться на `P:`. **Ограничения:** названий у контрагентов нет (только `U_…`), поэтому для поиска упоминаний в новостях они бесполезны; доли в оборотах (`share_pct`) нет, потому что общий оборот компании неизвестен |

## 6. Как проверить

```bash
# без сети и ключа (из корня репозитория)
backend/.venv/Scripts/python -m unittest llm.tests.test_offline llm.tests.test_digest_qa agent.tests.test_agent agent.tests.test_heuristic -v
cd backend && uv run pytest -rs          # в том числе tests/test_digest_db.py, test_questions.py, test_refresh.py
uv run python scripts/tag_documents.py   # переразметить документы после правки словаря

# с ключом (нужен LLM_API_KEY в .env), один раз — записать ответы для replay
LLM_MODE=live ML_MODE=real uv run python scripts/seed_demo.py --skip-ingest
# затем в /docs: GET /companies/U_67064/digest?period=week, POST /insights/{id}/ask
```

Перед коммитом `replay_cache/` проверьте, можно ли публиковать кэш: в промптах есть строки компаний из кейса (открытый вопрос из `agent/README.md`).
