# API-контракт News2Value (для фронтенда)

Сейчас API отдаёт **моковые (выдуманные) данные**: форма ответов уже окончательная, а содержимое позже заменят настоящими данными. Всё, что вы создадите или измените через API, живёт в памяти сервера и пропадает после его перезапуска.

- Адрес локально: `http://localhost:8000`
- Интерактивная документация (можно нажимать и пробовать): `http://localhost:8000/docs`
- Полная машинная схема: [openapi.json](openapi.json) (из неё можно сгенерировать типы для TypeScript)
- Авторизации нет.
- CORS (разрешение браузеру ходить в API с другого адреса) включён для `http://localhost:3000` и `http://localhost:5173`. Другие адреса добавляются в настройке `CORS_ORIGINS`.

Тестовые данные: три компании — `c-001` (производство), `c-002` (логистика), `c-003` (розница), у каждой 7–8 инсайтов.

## Общие правила

### Коды ответов

| Ситуация | Код |
|---|---|
| Любой GET | 200 с телом |
| `POST /companies` | 201 и созданный объект |
| `PUT /companies/{id}/profile` | 200 и обновлённый профиль |
| `POST .../insights/refresh`, `POST /insights/{id}/ask` | 202 и `{"job_id": "..."}` — работа идёт в фоне |
| `POST /insights/{id}/feedback` | 201 — первый отзыв на инсайт, 200 — отзыв обновлён |
| `DELETE /companies/{id}` | 204, тела нет |
| Несуществующий id | 404 |
| Неверные параметры или тело запроса | 422 |
| Неожиданный сбой сервера | 500 |

### Даты

- Фильтры `date_from` и `date_to`: только дата `YYYY-MM-DD`, обе границы **включительно**. Формат вроде `21.10.2026` даёт 422.
- Время событий (`created_at`, `published_at`): ISO 8601 в UTC с буквой `Z`, например `2026-10-21T14:30:00Z`. Смещений вида `+03:00` в ответах нет, переводить в местное время нужно на стороне фронтенда.

### Списки

Все списки (`GET /companies`, `GET /companies/{id}/insights`) возвращают одну и ту же форму:

```json
{"items": [ ... ], "total": 7, "limit": 20, "offset": 0}
```

`total` — сколько записей нашлось всего (с учётом фильтров, но без учёта `limit`/`offset`). Параметры: `limit` от 1 до 100 (по умолчанию 20), `offset` от 0 (по умолчанию 0).

### Ошибки

Все ошибки приходят в одной форме:

```json
{"error": "код_ошибки", "detail": "понятное описание"}
```

Коды: `not_found` (404), `validation_error` (422), `method_not_allowed` (405), `internal_error` (500). Текст ошибки показывать пользователю не нужно — ориентируйтесь на код ответа и поле `error`.

Пример 404:
```json
{"error": "not_found", "detail": "Компания xxx не найдена"}
```

Пример 422:
```json
{"error": "validation_error", "detail": "date_from: Input should be a valid date or datetime, invalid character in year"}
```

Пример 500 (подробности только в логах сервера, в ответ они не попадают):
```json
{"error": "internal_error", "detail": "Внутренняя ошибка сервера"}
```

### Что добавлено сверх списка лида

Следующие схемы не входили в исходный список от лида, их добавили для ask, feedback и общих правил: `AskRequest`, `AskResult`, `FeedbackRequest`, `Feedback`, `ErrorResponse`. Кроме них добавлены вспомогательные `CompanyCreate` (тело `POST /companies`), `JobAccepted` (ответ 202 `{job_id}`) и `Page` (форма списка). Поле `manual_data` в `CompanyProfile` тоже добавлено по отдельному решению (см. «Профиль компании»). Также добавлен эндпоинт `GET /jobs/{job_id}/result`. Для агента (22.10) добавлены параметр `role` у `refresh`, необязательные поля инсайта (`details`, `used_profile_fields`, `role`, `generated_by`, `prompt_version`) и `GET /jobs/{job_id}/run`.

## Компании

### GET /companies — список компаний
Параметры: `limit`, `offset`.
```json
{
  "items": [
    {"id": "c-001", "name": "АО «Заречье-Металл»", "industry": "Производство", "region": "Свердловская область", "revenue_bln_rub": 42.5}
  ],
  "total": 3,
  "limit": 20,
  "offset": 0
}
```

### GET /companies/{id} — одна компания
```json
{"id": "c-001", "name": "АО «Заречье-Металл»", "industry": "Производство", "region": "Свердловская область", "revenue_bln_rub": 42.5}
```
404, если компании нет.

### POST /companies — создать компанию (201)
Тело (все поля обязательны, `id` назначает сервер):
```json
{"name": "ООО «Новая»", "industry": "Строительство", "region": "Тульская область", "revenue_bln_rub": 3.2}
```
Ответ:
```json
{"id": "c-5a02485d", "name": "ООО «Новая»", "industry": "Строительство", "region": "Тульская область", "revenue_bln_rub": 3.2}
```

### DELETE /companies/{id} — удалить компанию (204)
Тела ответа нет. Вместе с компанией удаляются её профиль и инсайты. 404, если компании нет.

## Профиль компании

### GET /companies/{id}/profile
Для существующей компании всегда 200. Если профиль ещё не заполняли, поля, известные из данных компании (`industry`, `regions`), заполнены, остальные списки пустые, а `manual_data` равен `{}`. 404 — только если нет самой компании.
```json
{
  "company_id": "c-002",
  "industry": "Логистика",
  "regions": ["Краснодарский край", "Ростовская область"],
  "key_clients": ["ООО «Зелёный Берег»", "АО «ЮгАгроЭкспорт»"],
  "key_suppliers": ["ООО «ТопливоСнаб»", "ООО «Шинный Двор»"],
  "raw_materials": ["дизельное топливо", "шины", "запчасти для грузовиков"],
  "currency_risks": ["лизинг техники в евро"],
  "debt_load": "высокая: основная часть парка куплена в лизинг",
  "strategic_goals": ["открыть склад-хаб под Ростовом", "обновить 30% парка"],
  "bank_products": ["овердрафт", "лизинг", "зарплатный проект"],
  "manual_data": {}
}
```

### PUT /companies/{id}/profile — заменить профиль (200)
Тело и ответ такие же, как в примере выше. `company_id` берётся из адреса, значение в теле игнорируется. Профиль заменяется целиком: поля, которых нет в теле, станут пустыми. В `manual_data` можно положить любой JSON-объект.

## Инсайты

### GET /companies/{id}/insights — список инсайтов компании
Сортировка: сначала самые свежие (`created_at` по убыванию).

| Параметр | Что делает |
|---|---|
| `type` | `risk`, `opportunity` или `event` |
| `min_importance` | только инсайты с важностью не ниже (0–100) |
| `date_from`, `date_to` | дата создания от/до, `YYYY-MM-DD`, включительно |
| `limit`, `offset` | постраничный вывод |

Пример: `GET /companies/c-001/insights?type=risk&min_importance=80&limit=5`
```json
{
  "items": [
    {
      "id": "i-001",
      "company_id": "c-001",
      "title": "Металлопрокат подорожал на 12% за месяц",
      "summary": "Цены на листовой прокат выросли второй месяц подряд из-за сокращения выплавки у региональных комбинатов.",
      "type": "risk",
      "importance": 85,
      "impact_on_company": "Листовая сталь — основная статья затрат «Заречья-Металл»; рост на 12% съедает почти половину маржи по текущим контрактам с фиксированной ценой.",
      "recommended_action": "Закупить сталь на 2–3 месяца вперёд по текущей цене и пересмотреть цены в новых контрактах.",
      "sources": [
        {"title": "Комбинаты сокращают выплавку: прокат дорожает", "url": "https://news.example.org/prokat-rost", "published_at": "2026-10-19T12:00:00Z", "source_kind": "external"},
        {"title": "Обзор рынка чёрных металлов, октябрь", "url": "https://analytics.example.org/bank/metals-oct", "published_at": "2026-10-18T09:00:00Z", "source_kind": "bank_analytics"}
      ],
      "created_at": "2026-10-20T08:15:00Z"
    }
  ],
  "total": 1,
  "limit": 5,
  "offset": 0
}
```
Если ничего не подошло, вернётся `{"items": [], "total": 0, "limit": 20, "offset": 0}` с кодом 200. 404 — если нет компании, 422 — если параметры неверные.

### GET /insights/{id} — один инсайт
Тело такое же, как у элемента списка выше. 404, если инсайта нет.

Поля инсайта: `type` — `risk` (риск), `opportunity` (возможность) или `event` (событие); `importance` — число 0–100; `source_kind` у источника — `external` (внешняя новость) или `bank_analytics` (аналитика банка).

#### Необязательные поля от агента

У инсайтов, которые создал агент (после `refresh`), есть ещё пять полей. В моках они `null` / пустые, поэтому фронт может их не читать, а карточка из основных полей работает как раньше.

| Поле | Что это |
|---|---|
| `details` | Полная карточка из 6 блоков (схема `Insight` в `llm/schemas.py`): `headline`, `what_happened` (01), `why_it_matters` (02), `consequences` (03), `actions` (04), `bank_view` (05), `company_features_used` (06), `data_gaps`. У каждого утверждения `origin` — `fact` (факт из новости), `bank` (позиция Альфа-Банка) или `ai` (вывод модели) — и `source_ids`. В `details.agent` — релевантность, слагаемые скоринга и заметки самопроверки |
| `used_profile_fields` | Признаки компании, на которые опирался вывод: `F:<КОЛОНКА>` из данных банка, `G:<группа>` |
| `role` | Для какой роли читателя сделан инсайт (см. `refresh`) |
| `generated_by` | `llm` — написала модель; `rules` — модель недоступна (нет ключа, лимит, промах кэша), карточка собрана по шаблонам |
| `prompt_version` | Версия промпта интерпретации |

Метки «факт / банк / ИИ» для интерфейса — это `origin` в `details`. Источник утверждения находится по `source_ids`: `N:<id>` — новость, `A:<док>:<фрагмент>` — аналитика банка, обе есть в `sources`.

## Дайджест

### GET /companies/{id}/digest?period=day|week
Параметр `period` обязателен (`day` или `week`). В `insight_ids` — id инсайтов за период, самые важные первыми; сами инсайты берутся через `GET /insights/{id}`. В моках «сегодня» — дата самого свежего инсайта компании, поэтому дайджест не пустеет со временем.
```json
{
  "company_id": "c-002",
  "period": "day",
  "summary": "За сутки: 1 инсайт(ов), из них рисков — 1, возможностей — 0. Самое важное: Дизельное топливо дорожает третью неделю.",
  "insight_ids": ["i-008"]
}
```

## Фоновые задачи

Обновление инсайтов и ответ на вопрос выполняются в фоне. Схема работы: запустили → получили `job_id` → спрашиваем статус через `GET /jobs/{job_id}`, пока не будет `done` или `failed`.

### POST /companies/{id}/insights/refresh — обновить инсайты (202)
Запускает агента: он находит новости, отбирает важные для компании и пишет по ним инсайты. Когда задача `done`, **новые инсайты компании заменяют все прежние**. Если агент упал, задача `failed`, а прежние инсайты остаются.

Тело не нужно. Параметр `role` (необязательный, по умолчанию `ceo`) — роль читателя: меняет и отбор новостей, и акценты в тексте. Значения: `owner` (собственник), `ceo` (гендиректор), `cfo` (финдиректор), `treasurer` (казначейство), `accountant` (главный бухгалтер), `procurement` (закупки и логистика). Для переключателя роли: `POST .../refresh?role=cfo` → ждать `done` → заново `GET .../insights`.

404, если нет компании; 422, если роль неизвестна.
```json
{"job_id": "job-db608f7f"}
```

Пока источника новостей в бэкенде нет, агент берёт выдуманные новости из `agent/data/mock_news.json` (заголовки с пометкой `[MOCK]`).

### GET /jobs/{job_id}/run — план и трейс агента (для панели трассировки)
Только для завершённой (`done`) задачи `refresh`; иначе 404.
```json
{
  "run_id": "c-001-cfo-20261022-213000-1a2b",
  "role": "cfo",
  "llm_mode": "stub",
  "plan": ["Читатель: финансовый директор — ...", "Найти новости за 30 дн. ..."],
  "trace": [
    {"step": 1, "name": "Профиль компании", "tool": "get_company_profile", "input": {...}, "output": {...}, "status": "ok", "duration_ms": 0, "note": null},
    {"step": 3, "name": "Поиск новостей", "tool": "get_relevant_news", "status": "fallback", "note": "mock (источник новостей не подключён)", "...": "..."}
  ],
  "llm_usage": {"calls": 0, "replayed": 0, "tokens": 0, "cost_rub_est": 0.0, "errors": 0, "cache_hits": 0, "schema_retries": 0}
}
```
`status` шага: `ok`, `fallback` (сработала заглушка или откат), `skipped`, `error`.

### GET /jobs/{job_id} — статус задачи
`status`: `pending` (ждёт), `running` (идёт), `done` (готово), `failed` (ошибка, текст в `error`).
```json
{"id": "job-db608f7f", "status": "done", "error": null}
```
404, если задачи нет.

### GET /jobs/{job_id}/result — результат задачи ask
Работает только для задач, созданных через `ask`, и только когда задача `done`. Для refresh-задач, для ещё не готовых и для несуществующих задач вернётся 404.
```json
{
  "answer": "По теме «Металлопрокат подорожал на 12% за месяц»: Закупить сталь на 2–3 месяца вперёд по текущей цене и пересмотреть цены в новых контрактах. Вопрос был: «Как закупить сталь выгоднее?». Это демонстрационный ответ.",
  "sources": [
    {"title": "Комбинаты сокращают выплавку: прокат дорожает", "url": "https://news.example.org/prokat-rost", "published_at": "2026-10-19T12:00:00Z", "source_kind": "external"}
  ]
}
```

## Вопросы и отзывы по инсайту (заглушки модуля B7b)

### POST /insights/{id}/ask — задать вопрос по инсайту (202)
Тело (`question` не пустой):
```json
{"question": "Как закупить сталь выгоднее?"}
```
Ответ:
```json
{"job_id": "job-02a91ea4"}
```
Дальше: `GET /jobs/{job_id}` до статуса `done`, затем `GET /jobs/{job_id}/result`. 404, если инсайта нет; 422, если вопрос пустой.

### POST /insights/{id}/feedback — оценить инсайт
Тело: `rating` — `useful` или `not_useful`; `comment` необязателен, до 500 символов (длиннее — 422).
```json
{"rating": "useful", "comment": "Пригодилось"}
```
Первый отзыв на инсайт возвращает **201**, повторный на тот же инсайт обновляет существующий и возвращает **200**. Ответ в обоих случаях:
```json
{"insight_id": "i-001", "rating": "useful", "comment": "Пригодилось", "created_at": "2026-10-21T14:21:40Z"}
```
