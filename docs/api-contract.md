# API-контракт News2Value (для фронтенда)

**Компании и профили** (`/companies`, `/companies/{id}`, `/companies/{id}/profile`) работают с базой данных: в ней компании из данных банка (сейчас это сгенерированный датасет) и компании, созданные через API. Изменения сохраняются.

**Инсайты, дайджест, вопросы (ask) и оценки (feedback)** с модулей B7/B7b тоже работают с базой: лента показывает инсайты, которые сделал агент при `refresh`, вопросы и оценки сохраняются.

**Запасной режим `USE_MOCKS=true`** (настройка сервера, для демо без базы): инсайты, дайджест, ask и feedback снова берутся из **моковых (выдуманных) данных** в памяти сервера, как до B7, и пропадают после перезапуска. Компании, профили и refresh и в этом режиме работают с базой.

- Адрес локально: `http://localhost:8000`
- Интерактивная документация (можно нажимать и пробовать): `http://localhost:8000/docs`
- Полная машинная схема: [openapi.json](openapi.json) (из неё можно сгенерировать типы для TypeScript)
- Вход (B8+B9): `POST /auth/login` → токен, дальше заголовок `Authorization: Bearer <токен>` (см. раздел «Вход и права»). По умолчанию на сервере `AUTH_ENABLED=false`: токен не нужен, все запросы идут от пользователя `demo` с правами администратора.
- CORS (разрешение браузеру ходить в API с другого адреса) включён для `http://localhost:3000` и `http://localhost:5173`. Другие адреса добавляются в настройке `CORS_ORIGINS`.

**Демо-компании** с готовыми инсайтами (после `scripts/seed_demo.py`): `U_67064` (строительство жилья), `U_19717` (сеть АЗС), `U_16346` (интернет-торговля). У остальных компаний лента пустая, пока для них не нажали «Обновить» (`refresh`): `GET /companies/{id}/insights` отвечает 200 с `"items": []` и подсказкой в поле `hint`. Это нормальное состояние, а не ошибка.

Моковые компании `c-001`…`c-003` (производство, логистика, розница) с 7–8 выдуманными инсайтами есть только в режиме `USE_MOCKS=true`. В обычном режиме их нет в базе, и `GET /companies/c-001/insights` отвечает 404.

## Общие правила

### Коды ответов

| Ситуация | Код |
|---|---|
| Любой GET | 200 с телом |
| `POST /companies` | 201 и созданный объект |
| `PUT /companies/{id}/profile` | 200 и обновлённый профиль |
| `POST .../insights/refresh` | 202 и `{"job_id": "..."}` — работа идёт в фоне |
| `POST /insights/{id}/ask` | 202 и `{"job_id": "...", "question_id": "..."}`; 409 — уже 20 вопросов к инсайту |
| `POST /insights/{id}/feedback` | 201 — первая оценка пользователя на инсайт, 200 — оценка обновлена |
| `GET /insights/{id}/feedback` | 200 и оценка или `null`, если пользователь ещё не оценивал |
| `DELETE /companies/{id}` | 204, тела нет; 409 — компания из данных банка |
| Чужая компания (её профиль, лента, инсайт, задача); служебные эндпоинты и `POST`/`DELETE /companies` не администратором | 403 |
| Вход включён (`AUTH_ENABLED=true`), а токена нет, он неверный или истёк | 401 |
| `POST /auth/login`: неверный email или пароль | 401 |
| Несуществующий id | 404 |
| Неверные параметры или тело запроса | 422 |
| Неожиданный сбой сервера | 500 |

### Даты

- Фильтры `date_from` и `date_to`: только дата `YYYY-MM-DD`, обе границы **включительно**. Формат вроде `21.10.2026` даёт 422.
- Время событий (`created_at`, `published_at`): ISO 8601 в UTC с буквой `Z`, например `2026-10-21T14:30:00Z`. Смещений вида `+03:00` в ответах нет, переводить в местное время нужно на стороне фронтенда.

### Списки

Все списки (`GET /companies`, `GET /companies/{id}/insights`, `GET /insights/{id}/questions`) возвращают одну и ту же форму:

```json
{"items": [ ... ], "total": 7, "limit": 20, "offset": 0}
```

`total` — сколько записей нашлось всего (с учётом фильтров, но без учёта `limit`/`offset`). Параметры: `limit` от 1 до 100 (по умолчанию 20), `offset` от 0 (по умолчанию 0). У ленты инсайтов есть ещё два необязательных поля, `hint` и `refresh_job_id` (см. «Инсайты»).

### Ошибки

Все ошибки приходят в одной форме:

```json
{"error": "код_ошибки", "detail": "понятное описание"}
```

Коды: `unauthorized` (401), `forbidden` (403), `not_found` (404), `conflict` (409), `validation_error` (422), `method_not_allowed` (405), `internal_error` (500), `service_unavailable` (503 — на сервере не настроен вход). Текст ошибки показывать пользователю не нужно — ориентируйтесь на код ответа и поле `error`.

Пример 404:
```json
{"error": "not_found", "detail": "Компания xxx не найдена"}
```

Пример 422:
```json
{"error": "validation_error", "detail": "date_from: Input should be a valid date or datetime, invalid character in year"}
```

Пример 500 (подробности только в логах сервера, в ответ они не попадают):
```json
{"error": "internal_error", "detail": "Внутренняя ошибка сервера"}
```

### Что добавлено сверх списка лида

Следующие схемы не входили в исходный список от лида, их добавили для ask, feedback и общих правил: `AskRequest`, `AskResult`, `FeedbackRequest`, `Feedback`, `ErrorResponse`. Кроме них добавлены вспомогательные `CompanyCreate` (тело `POST /companies`), `JobAccepted` (ответ 202 `{job_id}`) и `Page` (форма списка). Поле `manual_data` в `CompanyProfile` тоже добавлено по отдельному решению (см. «Профиль компании»). Также добавлен эндпоинт `GET /jobs/{job_id}/result`. Для агента (22.10) добавлены параметр `role` у `refresh`, необязательные поля инсайта (`details`, `used_profile_fields`, `role`, `generated_by`, `prompt_version`) и `GET /jobs/{job_id}/run`. В модуле B3 (24.10) добавлены необязательные поля `revenue_known` и `source` в `Company`, параметр поиска `q` у `GET /companies`, ответ 409 у `DELETE`, поля профиля из данных банка и `field_sources`. Старые поля не менялись. В модуле B4 (24.10) добавлен служебный `GET /documents` (см. последний раздел) — фронтенду он не нужен.

**B7 и B7b (25.10), только добавления:** параметр `industry` и поля `hint`, `refresh_job_id` у ленты; поле `question_id` в ответе ask; эндпоинты `GET /insights/{id}/questions`, `GET /insights/{id}/feedback`, `GET /feedback/stats`; поля `reason` и `updated_at` у оценки; коды 401, 403 и 409 (лимит вопросов). Изменился только порядок ленты: раньше «свежие первыми», теперь «важные первыми». Совместимость с B1 проверяет тест `backend/tests/test_openapi_compat.py`. **Если вы генерируете типы TypeScript из `openapi.json`:** схема ответа ленты теперь называется `InsightPage` (была `Page_Insight_`; поля те же плюс два новых), ответ ask — `AskAccepted` (`JobAccepted` плюс `question_id`).

**B8+B9 (25.10), только добавления:** `POST /auth/login`, `GET /auth/me`, `GET /insights/{id}/trace`; коды 401 и 403 у всех эндпоинтов компаний, инсайтов и задач; 503 у входа. Без включённого входа всё работает как раньше.

## Вход и права (B8+B9)

### POST /auth/login — вход (200)
```json
{"email": "cfo.stroy@news2value.demo", "password": "..."}
```
Ответ:
```json
{
  "access_token": "eyJhbGciOi...",
  "token_type": "bearer",
  "expires_in": 43200,
  "user": {"id": "3", "email": "cfo.stroy@news2value.demo", "role": "cfo", "company_id": "U_67064", "is_admin": false, "auth_enabled": true}
}
```
Токен передаётся во всех запросах: `Authorization: Bearer <access_token>`, живёт `expires_in` секунд (12 часов). На неверный email и на неверный пароль ответ одинаковый: 401 `Неверный email или пароль`. Регистрации и восстановления пароля нет — тестовых пользователей создаёт сервер (см. README).

### GET /auth/me — кто я (200)
Тот же объект, что `user` в ответе входа. При `AUTH_ENABLED=false` — `{"id": "demo", "role": "admin", "is_admin": true, "auth_enabled": false, ...}`. По `auth_enabled` фронтенд понимает, показывать ли форму входа.

### Права
- Роли: `owner`, `ceo`, `cfo`, `treasurer` — видят только свою компанию (`company_id`); `admin` — все компании.
- `GET /companies` у не-администратора возвращает только его компанию.
- Профиль, лента, дайджест, refresh чужой компании, её инсайт (карточка, трассировка, вопросы, оценка) и задача (`/jobs/{id}`) → 403.
- Только admin: `POST /companies`, `DELETE /companies/{id}`, `GET /documents`, `GET /feedback/stats`.
- `refresh` без `role` берёт роль пользователя (у admin — `ceo`).
- Открыты всегда: `/health`, `/docs`, `/openapi.json`, `POST /auth/login`.

## Компании

### Поля компании

| Поле | Что это |
|---|---|
| `id` | Для компаний банка — id из данных банка (`U_67`), для созданных через API — `c-xxxxxxxx` |
| `name` | Название. У компаний банка названий в данных нет, поэтому `name` = `id`, пока его не задали вручную (через `PUT .../profile` или демо-профили) |
| `industry`, `region` | Отрасль (по ОКВЭД) и регион; `""`, если в данных пусто |
| `revenue_bln_rub` | Выручка. **Единицы пока не подтверждены:** у компаний банка значение отдаётся как в файле, без пересчёта, у созданных через API — как ввёл пользователь. До подтверждения не подписывайте его «млрд ₽». Имя поля оставлено ради совместимости |
| `revenue_known` | `true` — выручка известна. `false` — в данных было пусто или не число («Не определено»), тогда `revenue_bln_rub` = `0.0` — это заглушка, а не настоящий ноль: показывайте «нет данных». У созданных через API всегда `true` |
| `source` | `bank` — из данных банка, удалить нельзя; `manual` — создана через `POST /companies`, можно удалить. Кнопку «удалить» показывайте только при `manual` |

### GET /companies — список компаний
Параметры: `limit`, `offset` и необязательный `q` — поиск без учёта регистра по названию, id, отрасли и коду ОКВЭД (до 200 символов). Сортировка по `id`.

Пример: `GET /companies?q=торговля&limit=2`
```json
{
  "items": [
    {"id": "U_1", "name": "U_1", "industry": "Торговля розничная в неспециализированных магазинах", "region": "Томская область", "revenue_bln_rub": 150000.0, "revenue_known": true, "source": "bank"},
    {"id": "U_2", "name": "ООО «Напитки Демо»", "industry": "Торговля оптовая напитками", "region": "Москва", "revenue_bln_rub": 5000000.0, "revenue_known": true, "source": "bank"}
  ],
  "total": 3,
  "limit": 2,
  "offset": 0
}
```

### GET /companies/{id} — одна компания
```json
{"id": "U_4", "name": "U_4", "industry": "Разработка программного обеспечения", "region": "Омская область", "revenue_bln_rub": 0.0, "revenue_known": false, "source": "bank"}
```
404, если компании нет.

### POST /companies — создать компанию (201)
Тело (все поля обязательны, `id` назначает сервер):
```json
{"name": "ООО «Новая»", "industry": "Строительство", "region": "Тульская область", "revenue_bln_rub": 3.2}
```
Ответ:
```json
{"id": "c-5a02485d", "name": "ООО «Новая»", "industry": "Строительство", "region": "Тульская область", "revenue_bln_rub": 3.2, "revenue_known": true, "source": "manual"}
```

### DELETE /companies/{id} — удалить компанию (204)
Удаляются только компании с `source: "manual"`. Тела ответа нет, вместе с компанией удаляется её профиль. 404, если компании нет.

Компанию из данных банка удалить нельзя — 409:
```json
{"error": "conflict", "detail": "Компания U_67 загружена из данных банка, удалить её нельзя. Удаляются только компании, созданные через POST /companies"}
```

## Профиль компании

Профиль собирается из двух частей:
- **автоматической** (`auto`) — считается из данных банка при каждом запросе;
- **ручной** (`manual`) — то, что сохранили через `PUT` или демо-профили.

Если поле есть в обеих частях, побеждает ручное — даже пустое, переданное явно (например `"key_clients": []`). Откуда взято каждое поле, видно в `field_sources`.

### GET /companies/{id}/profile
Для существующей компании всегда 200, даже если данных мало: пустое поле — это `""`, `[]`, `0` или `null`, а не ошибка. 404 — только если нет самой компании.
```json
{
  "company_id": "U_2",
  "industry": "Торговля оптовая напитками",
  "regions": ["Москва"],
  "key_clients": [],
  "key_suppliers": ["U_1"],
  "raw_materials": ["стеклотара", "сахар"],
  "currency_risks": [],
  "debt_load": "",
  "strategic_goals": [],
  "bank_products": ["РКО", "Кредиты", "Зарплатный проект"],
  "manual_data": {},
  "name": "ООО «Напитки Демо»",
  "okved_code": "46.34.2",
  "city": "г. Москва",
  "revenue_bln_rub": 5000000.0,
  "revenue_known": true,
  "employees": "16-100",
  "foreign_trade": true,
  "foreign_trade_countries": ["КИТАЙ", "ТУРЦИЯ"],
  "group_id": "group_1_sb",
  "group_size": 2,
  "top_buyers": [
    {"company_id": "U_3", "name": "U_3", "industry": "Деятельность в области права", "amount": null, "is_known": true}
  ],
  "top_suppliers": [
    {"company_id": "U_1", "name": "U_1", "industry": "Торговля розничная в неспециализированных магазинах", "amount": 1500, "is_known": true}
  ],
  "field_sources": {"industry": "auto", "key_clients": "manual", "raw_materials": "manual", "name": "manual", "okved_code": "auto", "...": "..."}
}
```

| Поле | Откуда в auto |
|---|---|
| `name` | `id` компании (у созданных через API — введённое название, оно ручное) |
| `industry`, `okved_code` | Основной ОКВЭД: название и код |
| `regions`, `city` | Регион (списком из одного элемента) и город |
| `revenue_bln_rub`, `revenue_known` | Как в `Company` (единицы не подтверждены) |
| `employees` | Градация численности сотрудников (ФНС, если нет — СПАРК), например `"16-100"` |
| `bank_products` | Продукты банка по флагам: РКО, Гарантии, Кредиты, Лизинг, Депозиты, Зарплатный проект, Факторинг |
| `foreign_trade`, `foreign_trade_countries` | ВЭД (внешнеэкономическая деятельность): флаг (`null` — неизвестно) и страны |
| `group_id`, `group_size` | Группа компаний и сколько в ней компаний (включая эту); `0` — группы нет |
| `top_buyers`, `top_suppliers` | До 5 крупнейших покупателей (платят компании) и поставщиков (получают от неё) по сумме платежей. `amount` — сумма как в файле (`null` — в файле не число, такие в конце). `is_known: false` — контрагента нет в наших данных, отрасль `""` |
| `key_clients`, `key_suppliers` | Названия из `top_buyers` / `top_suppliers` |
| `raw_materials`, `currency_risks`, `debt_load`, `strategic_goals`, `manual_data` | В данных банка этого нет — только ручной ввод |

`field_sources` — объект «поле → `auto` | `manual`» для всех полей профиля, кроме `company_id` и самого `field_sources`.

### PUT /companies/{id}/profile — сохранить ручные поля (200)
В теле — только те поля профиля, которые пользователь ввёл или изменил. Ответ — весь объединённый профиль, как в `GET`.
```json
{"raw_materials": ["стеклотара", "сахар"], "key_clients": []}
```
- Поля из тела становятся ручными. **Ручные поля, которых нет в теле, сохраняются** (повторный `PUT` дописывает, а не стирает).
- Пустое значение (`[]`, `""`) — тоже ручное: оно скроет данные банка. Вернуть поле к автоматическому значению пока нельзя.
- **Не отправляйте обратно весь профиль из `GET`:** тогда все поля станут ручными и перестанут обновляться из данных банка.
- `company_id` и `field_sources` в теле можно передать, они игнорируются. Неизвестное поле, неверный тип (`"key_clients": "строка"` или `null`) или сломанный JSON — 422.
- Ручные `name`, `industry`, `regions` и `revenue_bln_rub` видны и в карточке компании (`GET /companies`, `GET /companies/{id}`).
- В `manual_data` по-прежнему можно положить любой JSON-объект.

## Инсайты

### GET /companies/{id}/insights — список инсайтов компании
Сортировка: сначала самые важные (`importance` по убыванию), при равной важности — свежие (`created_at` по убыванию). В режиме `USE_MOCKS=true` — как раньше, только по свежести.

| Параметр | Что делает |
|---|---|
| `type` | `risk`, `opportunity` или `event` |
| `min_importance` | только инсайты с важностью не ниже (0–100) |
| `date_from`, `date_to` | дата создания от/до, `YYYY-MM-DD`, включительно (по UTC); `date_from` позже `date_to` — 422 |
| `industry` | отрасль новости-источника: код ОКВЭД из двух цифр (`41` или `okved:41`, регистр не важен) или другой тег документа (`economy`). Подходят инсайты, у которых хотя бы одна новость-источник с таким тегом. Отрасль ставится новостям автоматически по ключевым словам, поэтому есть не у всех; у инсайтов, сделанных на моковых новостях агента, источников из базы нет, и под фильтр они не попадают |
| `limit`, `offset` | постраничный вывод |

Дополнительные поля ответа (оба необязательные):

| Поле | Что это |
|---|---|
| `hint` | Текст для пустой ленты, когда у компании ещё **нет ни одного инсайта**: `"Инсайты ещё не собраны, нажмите «Обновить»"`, а если обновление уже идёт — `"Инсайты собираются…"`. Если инсайты есть, но фильтры ничего не нашли, `hint` = `null` |
| `refresh_job_id` | id задачи `refresh`, которая сейчас выполняется (`null`, если её нет). Статус — `GET /jobs/{id}`; когда задача `done`, ленту нужно запросить заново. Кнопка «Обновить» — это `POST /companies/{id}/insights/refresh` |

Пример пустой ленты:
```json
{"items": [], "total": 0, "limit": 20, "offset": 0, "hint": "Инсайты ещё не собраны, нажмите «Обновить»", "refresh_job_id": null}
```

Пример: `GET /companies/c-001/insights?type=risk&min_importance=80&limit=5`
```json
{
  "items": [
    {
      "id": "i-001",
      "company_id": "c-001",
      "title": "Металлопрокат подорожал на 12% за месяц",
      "summary": "Цены на листовой прокат выросли второй месяц подряд из-за сокращения выплавки у региональных комбинатов.",
      "type": "risk",
      "importance": 85,
```

### GET /insights/{id} — один инсайт
Тело такое же, как у элемента списка выше. 404, если инсайта нет. Источники-новости в карточке берутся из собранных документов: актуальные заголовок, ссылка (`""`, если её нет) и дата публикации (если её нет — время сбора). У источника из базы есть `id` вида `N:doc-<номер>`. Новости, на которые ссылается разбор, но которых не было в `sources`, добавляются в конец. Тезисы банка (`A:…`) и моковые новости остаются как были. В ленте источники отдаются без этого обновления.

**Инсайт может пропасть.** Каждый `refresh` заменяет все инсайты компании. Если у нового инсайта тот же источник и та же роль, у него тот же id; иначе старый id даёт 404, и фронту нужно вернуться к ленте.

Поля инсайта: `type` — `risk` (риск), `opportunity` (возможность) или `event` (событие); `importance` — число 0–100; `source_kind` у источника — `external` (внешняя новость) или `bank_analytics` (аналитика банка).

#### Необязательные поля от агента

У инсайтов, которые создал агент (после `refresh`), есть ещё пять полей. В моках они `null` / пустые, поэтому фронт может их не читать, а карточка из основных полей работает как раньше.

| Поле | Что это |
|---|---|
| `details` | Полная карточка из 6 блоков (схема `Insight` в `llm/schemas.py`): `headline`, `what_happened` (01), `why_it_matters` (02), `consequences` (03), `actions` (04), `bank_view` (05), `company_features_used` (06), `data_gaps`. У каждого утверждения `origin` — `fact` (факт из новости), `bank` (позиция Альфа-Банка) или `ai` (вывод модели) — и `source_ids`. В `details.agent` — релевантность, слагаемые скоринга и заметки самопроверки |
| `used_profile_fields` | Признаки компании, на которые опирался вывод: `F:<КОЛОНКА>` из данных банка, `G:<группа>` |
| `role` | Для какой роли читателя сделан инсайт (см. `refresh`) |
| `generated_by` | `llm` — написала модель; `rules` — модель недоступна (нет ключа, лимит, промах кэша), карточка собрана по шаблонам |
| `prompt_version` | Версия промпта интерпретации |

Метки «факт / банк / ИИ» для интерфейса — это `origin` в `details`. Источник утверждения находится по `source_ids`: `N:<id>` — новость, `A:<док>:<фрагмент>` — аналитика банка, обе есть в `sources`.

### GET /insights/{id}/trace — как сделан инсайт (B8+B9)
Запуск `refresh`, который создал инсайт, его шаги со временем каждого (`duration_ms`), источники (у собранных документов — `document_id` и `source_name`), признаки профиля и версия промптов. Шаги — те же, что в `GET /jobs/{job_id}/run`, но доступны и без `job_id`. `used_profile_fields` и `prompt_version` равны `null`, если генератор их не отдал. `generated_by`: `llm` — модель, `rules` — шаблоны агента, `fake` — заглушка `ML_MODE=fake`. `run_id` — `null` у моковых инсайтов (`USE_MOCKS=true`) и у инсайтов, запуск которых удалён. 404 — нет инсайта, 403 — чужая компания.
```json
{
  "insight_id": "U_67064-doc-12-cfo",
  "company_id": "U_67064",
  "run_id": 41,
  "generator_run_id": "U_67064-cfo-20261025-101500-1a2b",
  "run_status": "done",
  "role": "cfo",
  "llm_mode": "stub",
  "started_at": "2026-10-25T10:15:00Z",
  "finished_at": "2026-10-25T10:15:03Z",
  "duration_ms": 3120,
  "steps": [{"step": 1, "name": "Профиль компании", "tool": "get_company_profile", "status": "ok", "duration_ms": 4, "note": null, "input": {}, "output": {}}],
  "sources": [{"id": "N:doc-12", "document_id": 12, "title": "...", "url": "https://...", "published_at": "2026-10-24T07:00:00Z", "source_kind": "external", "source_name": "interfax"}],
  "used_profile_fields": ["F:MAINOKVED_NAME", "F:REGION"],
  "prompt_version": "insight@v3",
  "generated_by": "rules"
}
```

## Дайджест

### GET /companies/{id}/digest?period=day|week
Параметр `period` обязателен (`day` или `week`). В `insight_ids` — до 10 самых важных инсайтов, созданных за последние сутки или неделю (от текущего момента), самые важные первыми; сами инсайты берутся через `GET /insights/{id}`. `summary` — сводка за период: её пишет модель, а если модель недоступна — склейка заголовков («За неделю: 3 инсайт(ов), из них рисков — 1… Главное: …»). Если инсайтов за период нет: `"summary": "Новых инсайтов нет."`, `"insight_ids": []`. Сводки хранятся в кэше: пока набор инсайтов и их важность не меняются, ответ мгновенный. 404 — нет компании, 422 — неверный `period`.

В режиме `USE_MOCKS=true` «сегодня» для моков — дата самого свежего инсайта компании, поэтому моковый дайджест не пустеет со временем.
```json
{
  "company_id": "c-002",
  "period": "day",
  "summary": "За сутки: 1 инсайт(ов), из них рисков — 1, возможностей — 0. Самое важное: Дизельное топливо дорожает третью неделю.",
  "insight_ids": ["i-008"]
}
```

## Фоновые задачи

Обновление инсайтов и ответ на вопрос выполняются в фоне. Схема работы: запустили → получили `job_id` → спрашиваем статус через `GET /jobs/{job_id}`, пока не будет `done` или `failed`.

### POST /companies/{id}/insights/refresh — обновить инсайты (202)
Ставит задачу агенту: он находит новости, отбирает важные для компании и пишет по ним инсайты. Ответ приходит сразу, работу делает отдельный фоновый процесс (worker). Когда задача `done`, **новые инсайты компании заменяют все прежние**. Если агент не нашёл ни одной карточки, задача тоже `done`, а прежние инсайты остаются. Если агент упал, задача `failed`, а прежние инсайты остаются.

**Одна задача на компанию.** Пока у компании есть задача `pending` или `running`, повторный `refresh` не создаёт новую, а возвращает `job_id` текущей, даже с другим `role`. Поэтому кнопку можно нажимать повторно: дубля не будет. Новый `refresh` с другой ролью имеет смысл после `done` / `failed`.

Новые инсайты сразу видны в `GET .../insights` и в дайджесте. Моковые компании `c-001`…`c-003` в БД не хранятся, и `refresh` для них возвращает 404.

Тело не нужно. Параметр `role` (необязательный; по умолчанию роль вошедшего пользователя, у admin и при выключенном входе — `ceo`) — роль читателя: меняет и отбор новостей, и акценты в тексте. Значения: `owner` (собственник), `ceo` (гендиректор), `cfo` (финдиректор), `treasurer` (казначейство), `accountant` (главный бухгалтер), `procurement` (закупки и логистика). Для переключателя роли: `POST .../refresh?role=cfo` → ждать `done` → заново `GET .../insights`.

404, если нет компании; 422, если роль неизвестна.
```json
{"job_id": "job-db608f7f"}
```

Откуда агент берёт новости, задаёт настройка сервера `NEWS_SOURCE`: `db` — собранные новости из базы (у карточки есть источники с `id` `N:doc-<номер>`, работает фильтр `industry`), `mock` — выдуманные новости из `agent/data/mock_news.json` (заголовки с пометкой `[MOCK]`).

### GET /jobs/{job_id}/run — план и трейс агента (для панели трассировки)
Только для завершённой (`done`) задачи `refresh`; иначе 404.
```json
{
  "run_id": "c-001-cfo-20261022-213000-1a2b",
  "role": "cfo",
  "llm_mode": "stub",
  "plan": ["Читатель: финансовый директор — ...", "Найти новости за 30 дн. ..."],
  "trace": [
    {"step": 1, "name": "Профиль компании", "tool": "get_company_profile", "input": {...}, "output": {...}, "status": "ok", "duration_ms": 0, "note": null},
    {"step": 3, "name": "Поиск новостей", "tool": "get_relevant_news", "status": "fallback", "note": "mock (источник новостей не подключён)", "...": "..."}
  ],
  "llm_usage": {"calls": 0, "replayed": 0, "tokens": 0, "cost_rub_est": 0.0, "errors": 0, "cache_hits": 0, "schema_retries": 0}
}
```
`status` шага: `ok`, `fallback` (сработала заглушка или откат), `skipped`, `error`.

### GET /jobs/{job_id} — статус задачи
`status`: `pending` (ждёт), `running` (идёт), `done` (готово), `failed` (ошибка, текст в `error`). Задача, которая была в `running` дольше 10 минут (фоновый процесс упал), переводится в `failed` с пояснением в `error`. Опрашивать статус удобно раз в 1–2 секунды.
```json
{"id": "job-db608f7f", "status": "done", "error": null}
```
404, если задачи нет.

### GET /jobs/{job_id}/result — результат задачи ask
Работает только для задач, созданных через `ask`, и только когда задача `done`. Для refresh-задач, для ещё не готовых и для несуществующих задач вернётся 404. Тот же ответ сохраняется в истории вопросов (`GET /insights/{id}/questions`). `sources` — источники инсайта, на которые опирается ответ.
```json
{
  "answer": "По теме «Металлопрокат подорожал на 12% за месяц»: Закупить сталь на 2–3 месяца вперёд по текущей цене и пересмотреть цены в новых контрактах. Вопрос был: «Как закупить сталь выгоднее?». Это демонстрационный ответ.",
  "sources": [
    {"title": "Комбинаты сокращают выплавку: прокат дорожает", "url": "https://news.example.org/prokat-rost", "published_at": "2026-10-19T12:00:00Z", "source_kind": "external"}
  ]
}
```

## Вопросы и оценки по инсайту (модуль B7b)

Ответ на вопрос готовит модель. Если модель недоступна, приходит ответ-шаблон по полям инсайта с его источниками. Стриминга (ответа по кускам) нет: ответ приходит целиком, когда задача `done`.

### POST /insights/{id}/ask — задать вопрос по инсайту (202)
Тело: `question` — от 1 до 500 символов; пробелы по краям обрезаются, вопрос из одних пробелов — 422.
```json
{"question": "Как закупить сталь выгоднее?"}
```
Ответ:
```json
{"job_id": "job-02a91ea4", "question_id": "q-5c1e9a0b"}
```
Дальше: `GET /jobs/{job_id}` до статуса `done` (или `failed`), затем `GET /jobs/{job_id}/result` или `GET /insights/{id}/questions`. К одному инсайту можно задать **не больше 20 вопросов** (все пользователи вместе), 21-й вернёт 409:
```json
{"error": "conflict", "detail": "Лимит 20 вопросов к инсайту U_67064-doc-62-ceo исчерпан"}
```
404 — инсайта нет; 403 — инсайт компании, к которой у пользователя нет доступа; 422 — вопрос пустой или длиннее 500 символов. Если до ответа `refresh` заменил инсайты компании, задача станет `failed` с пояснением в `error`.

### GET /insights/{id}/questions — история вопросов (200)
Вопросы текущего пользователя по инсайту и ответы на них, **старые первыми**, в форме списка (`limit`, `offset`). Пока `status` не `done`, `answer` = `null` и `sources` = `[]`. `status` повторяет статус задачи: `pending`, `running`, `done`, `failed`.
```json
{
  "items": [
    {
      "id": "q-5c1e9a0b",
      "insight_id": "U_67064-doc-62-ceo",
      "question": "Что это значит для наших продаж?",
      "answer": "Льготная ипотека не расширится, поэтому спрос на новостройки…",
      "sources": [{"id": "N:doc-62", "title": "Набиуллина выступила против увеличения объемов льготной ипотеки", "url": "https://www.kommersant.ru/doc/…", "published_at": "2026-10-24T10:15:00Z", "source_kind": "external"}],
      "status": "done",
      "job_id": "job-02a91ea4",
      "created_at": "2026-10-25T09:00:00Z"
    }
  ],
  "total": 1, "limit": 20, "offset": 0
}
```
404 — инсайта нет; 403 — нет доступа.

### POST /insights/{id}/feedback — оценить инсайт
Тело: `rating` — `useful` или `not_useful`; `reason` — необязательная причина, **только при `not_useful`**: `inaccurate` (неточно), `irrelevant` (не про нас), `unclear` (непонятно), `other` (другое). `reason` при `useful` — 422. `comment` необязателен, до 500 символов (длиннее — 422).
```json
{"rating": "not_useful", "reason": "irrelevant", "comment": "Мы не работаем с Турцией"}
```
**Один пользователь — одна оценка на инсайт.** Первая оценка возвращает **201**, повторная обновляет прежнюю (`rating`, `reason`, `comment`) и возвращает **200**. Ответ в обоих случаях:
```json
{"insight_id": "i-001", "rating": "not_useful", "comment": "Мы не работаем с Турцией", "created_at": "2026-10-21T14:21:40Z", "reason": "irrelevant", "updated_at": "2026-10-21T14:25:02Z"}
```
`created_at` — время первой оценки, `updated_at` — последнего изменения. Оценки сохраняются и после `refresh`.

### GET /insights/{id}/feedback — моя оценка (200)
Нужна, чтобы подсветить выбранную кнопку. Ответ — объект, как у `POST` выше, или `null`, если пользователь ещё не оценивал инсайт (это не ошибка). 404 — инсайта нет; 403 — нет доступа.

### GET /feedback/stats — метрики качества (только администратор)
Сводка по всем оценкам. `useful_share` — доля `useful` от 0 до 1 (`null`, если оценок нет). `by_reason` — причины у оценок `not_useful` (`none` — без причины). `by_type` — по типу инсайта. Все ключи есть всегда, даже с нулями.
```json
{
  "total": 8, "useful": 5, "not_useful": 3, "useful_share": 0.625,
  "by_reason": {"inaccurate": 1, "irrelevant": 1, "unclear": 0, "other": 0, "none": 1},
  "by_type": {
    "risk": {"total": 4, "useful_share": 0.25},
    "opportunity": {"total": 2, "useful_share": 1.0},
    "event": {"total": 2, "useful_share": 1.0}
  }
}
```
403 — пользователь не администратор. Пока входа нет, все запросы от `demo`, а он администратор.

## Служебные эндпоинты (internal, не для фронтенда)

Нужны бэкенду и команде, чтобы проверить сбор данных. В интерфейсе их не показывать; в `/docs` они в группе `internal`, у названия пометка `[internal]`. Форма ответа может меняться без предупреждения.

### GET /documents — собранные документы (модуль B4)

Документы из RSS-лент (`external_news`) и PDF-аналитики банка (`bank_analytics`), сначала свежие (по `published_at`; документы без даты — в конце). Полный текст не отдаётся — только первые 500 символов и длина.

Параметры (все необязательные): `kind` — `external_news` или `bank_analytics`; `date_from`, `date_to` — `YYYY-MM-DD`, дата публикации по UTC, обе включительно; `limit` (1–100, по умолчанию 20), `offset`. С фильтром по датам документы без даты публикации не попадают. 422 — неверный `kind`, дата не в формате `YYYY-MM-DD`, `date_from` позже `date_to`.

```json
{
  "items": [
    {
      "id": 42,
      "kind": "external_news",
      "source_name": "kommersant_economics",
      "url": "https://www.kommersant.ru/doc/0000000",
      "title": "Заголовок статьи",
      "text_preview": "Первые 500 символов текста…",
      "text_length": 2177,
      "published_at": "2026-10-23T18:53:56Z",
      "tags": ["economy"],
      "content_hash": "3f0c…(sha256)",
      "fetched_at": "2026-10-24T17:27:38Z",
      "status": "ok"
    }
  ],
  "total": 69, "limit": 20, "offset": 0
}
```

`status`: `ok` — текст есть; `empty_text` — текст не извлёкся (например, PDF из картинок без текстового слоя); `error` — документ не удалось получить. `url` у PDF — `local://<папка>/<файл>`. Тег `text_from_summary` — статью скачать не удалось, текст взят из описания в RSS.
