# Безопасность прототипа News2Value

Это прототип для хакатона. Здесь честно сказано, что защищено и что нет.

## Что сделано

- **Вход и права.** Пароли хранятся только как bcrypt-хеш (по нему пароль не восстановить). `POST /auth/login` выдаёт JWT — подписанный токен на 12 часов (`JWT_EXPIRE_MINUTES`). При `AUTH_ENABLED=true` без токена — 401. Пользователь видит только свою компанию, на чужую — 403. Администратор видит все компании и служебные эндпоинты (`/documents`, `/feedback/stats`). Если пользователя удалили, его токен перестаёт работать сразу.
- **Одинаковый ответ на неверный email и неверный пароль**, чтобы по ответу нельзя было узнать, есть ли такой пользователь.
- **Журнал `audit_log`.** Каждый вызов ML-функции (в том числе неудачный) и каждый вход: кто, когда, какая функция, id входных данных, статус, время, токены. Тексты новостей, профилей и вопросов в журнал не пишутся, у неудачного входа email замаскирован (`d***@g***.com`).
- **Маскирование логов.** Email, токены (`Bearer …`, JWT), ключи `sk-…`, значения `password=`/`token=`/`api_key=`, пароль в адресе БД и точные значения секретов из `.env` заменяются на `***`. Это касается и трейсбеков. Слишком длинные сообщения обрезаются до 2000 символов.
- **Секреты только в `.env`**, файл в `.gitignore`. В git лежит шаблон `.env.example` с заглушками. При `AUTH_ENABLED=true` и пустом `JWT_SECRET` API не запускается.
- **Дневной лимит токенов модели** (`LLM_DAILY_TOKEN_LIMIT`): после него задачи получают понятную ошибку, сервис продолжает работать. У агента есть свой лимит в рублях (`LLM_DAILY_BUDGET_RUB`).
- **На сервере база не открыта наружу**: у неё нет опубликованного порта. Наружу смотрит только Caddy (80/443), с доменом он сам включает HTTPS.
- **Ошибки 500** отдаются клиенту без подробностей: трейсбек остаётся только в логе сервера.
- **Сбор новостей** соблюдает robots.txt и паузы между запросами.

## Что не сделано (осознанно, для прототипа)

- Нет регистрации, восстановления пароля, OAuth и входа из интернет-банка: вход из Альфа-Бизнес только смоделирован.
- Нет отзыва токенов (выхода) и ограничения числа попыток входа: подбор пароля не тормозится.
- У всех тестовых пользователей один пароль (`DEMO_USER_PASSWORD`).
- **По умолчанию `AUTH_ENABLED=false`**: все запросы идут от администратора `demo`. Для показа на сервере вход нужно включить.
- Без домена сервер работает по HTTP, токен и пароль идут открытым текстом.
- База не шифруется на диске, резервных копий нет. Секреты в `.env` на сервере лежат открытым текстом.
- В `replay_cache/` (он в git) лежат промпты и ответы модели. В них могут быть поля профиля демо-компаний, но не данные из `data/raw`.
- Журнал `audit_log` не защищён от изменения администратором базы и не чистится сам.
- Проверка зависимостей на уязвимости и тесты на проникновение не проводились.
- CSV банка (`data/raw/`) в git не попадают, но на сервере, куда их скопировали, лежат без шифрования.
