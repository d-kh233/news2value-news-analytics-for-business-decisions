# agent/ — агентный оркестратор (зона тимлида)

Профиль компании → план → поиск новостей → разметка (если не размечены) → скоринг с учётом роли →
аналитика Альфа-Банка → интерпретация → самопроверка → инсайты в формате бэкенда.
Каждый шаг пишется в трейс. Зависимость одна — `pydantic` (есть в бэкенде).

Своих промптов и схем у агента нет: всё берётся из `llm/` промпт-инженера.

| что | откуда |
|---|---|
| разметка новости | `llm.extract.extract_event` |
| влияние на отрасль | `llm.okved.sensitivity.macro_impact` + `okved_sensitivity.csv` |
| промпт, контекст, роли, проверка источников | `llm.insight` (`build_context`, `ROLES`) |
| вызов модели с исправлением по схеме | `llm.client.call_json` |
| карточка из 6 блоков | `llm.schemas.Insight` |
| перевод в формат бэкенда | `llm.backend_adapter.to_backend_insight` |

Что добавляет сам агент:
- отбор и ранжирование;
- поиск по тезисам банка;
- строгую самопроверку;
- откат на правила;
- LLM-шлюз с режимами, записью ответов и лимитом;
- трейс.

## Как вызывается

Бэкенд: `POST /companies/{id}/insights/refresh?role=cfo` → фоновая задача →
`backend/app/ml_ports/agent_port.py` → `Orchestrator().run(profile, role=...)` → инсайты заменяют
прежние инсайты компании. План и трейс отдаёт `GET /jobs/{job_id}/run`. Контракт: `docs/api-contract.md`.

Профиль компании:
- компания из таблицы `companies` — строка БД как есть;
- моковая или созданная через API — `Company` + `CompanyProfile`. ОКВЭД берётся из `manual_data.MAINOKVED_CODE`, флаги продуктов — из `manual_data`, а если их нет — угадываются по тексту `bank_products`.

Без бэкенда, из корня репозитория:

```bash
python -m agent run --company MOCK-002 --role cfo           # карточки в консоли
python -m agent run --company MOCK-002 --role cfo --json    # полный прогон: инсайты + план + трейс
python -m agent inspect-csv data/raw/df_Uid_data_hack.csv   # что увидит модель по реальному файлу
python -m agent roles
python -m agent eval                                        # качество отбора на размеченном наборе
python -m unittest agent.tests.test_agent -v                # тесты агента (без сети и ключа)
python -m unittest llm.tests.test_offline -v                # тесты llm/
cd backend && uv run pytest                                 # тесты бэкенда, включая tests/test_agent_refresh.py
```

## Режимы LLM (`LLM_MODE` в `.env`)

| режим | сеть | что происходит |
|---|---|---|
| `stub` | нет | карточки по шаблонам `agent/rules.py`, неразмеченные новости не ранжируются. По умолчанию и в тестах |
| `live` | да | вызовы модели; каждый ответ пишется в `replay_cache/llm/calls/`, расход — в `usage-ДАТА.json`, лимит `LLM_DAILY_BUDGET_RUB` |
| `replay` | нет | ответы только из записи. Промах → откат на правила с пометкой в трейсе. Это режим для жюри |

**Почему у шлюза своя запись.** Кэш `call_json` хранит только ответы, прошедшие проверку. Если модель исправлялась после самопроверки, первый неудачный ответ туда не попадает, и replay до исправления не дойдёт. Шлюз пишет каждый ответ, поэтому replay повторяет весь диалог.

**Дата прогона.** Для replay задайте `AGENT_TODAY` той же датой, что при записи. От неё зависят свежесть и отбор новостей, а значит и промпты.

**Как записать демо.** На каждом демо-профиле и в каждой роли, которую покажем, один раз прогоните `LLM_MODE=live`. Затем закоммитьте `replay_cache/`. Каждая роль — отдельные вызовы модели: 3 роли × 3–5 профилей × 5 карточек.

## Самопроверка

- **Её проверка** (`_check_sources`): только переданные id источников; блок «почему важно» опирается на признаки компании.
- **Строгая проверка агента** (`generator.strict_check`): в фактах (01) нет чисел, которых нет в новости; `origin=bank` только со ссылкой на `A:`; `origin=fact` только со ссылкой на новость или данные компании.

Обе проверки стоят в цикле исправления `call_json`: модель видит текст ошибки и переписывает ответ. После ответа агент дополнительно:
- заменяет текст позиции банка (05) дословным тезисом;
- убирает утверждения без известного тезиса.

Всё, что исправлено, попадает в `details.agent.validation_notes`.

## Отбор и ранжирование

Два этапа:

1. **Отбор кандидатов** (`orchestrator._prefilter`) — до вызова модели. Лексическая близость новости к профилю (BM25 по отрасли, виду деятельности, сырью и целям) и упоминание сущностей компании. По этому скору агент выбирает, какие неразмеченные новости отдать на разметку (она платная, не больше 20 за прогон).
2. **Скоринг** (`scoring.py`) — после разметки.

| признак | откуда |
|---|---|
| `macro` | `macro_impact`: движение факторов × карта ОКВЭД аналитика × продукты компании, со знаком. Берётся сумма величин влияния (с весами роли) с плавным насыщением `1 − e^(−сумма/4)`, а не счёт 0–100: тот упирается в 100, и на решении по ставке у всех компаний выходило одинаково |
| `industry` | новость про отрасль компании (`okved_hints`) |
| `region` | событие в регионе компании |
| `entity` | в новости есть сущности компании (`entities.py`): страны ВЭД, сырьё и его другие названия, клиенты и поставщики, валюты. Слабые подсказки по продуктам («экспорт», «страховые взносы») учитываются только для правил и торговых мер |
| `sim` | BM25-близость к профилю |
| `event_type`, `freshness` | тип события (умножается на вес роли) и свежесть |

Формула: `link` × 0.50 + `both` × 0.10 + `sim` × 0.10 + тип × 0.15 + свежесть × 0.15.
- `link` = max(`macro`, отрасль 0.85, регион 0.6, сущности 0.8) — сила связи с компанией.

Штрафы:
- **Событие про чужую отрасль:** × 0.3 к макровлиянию, региону и косвенным сущностям. Работает для всех типов, кроме широких (ставка, инфляция, курс, сырьё, долговой рынок): «зарплаты разработчиков выросли» — «макро», но про одну отрасль. Сырьё, контрагенты и валюты компании штраф не снимают.
- **Мера про чужие страны** (торговля, санкции, регуляторика): у компании известны страны ВЭД, и ни одна не названа в новости — × 0.3 к макровлиянию.
- **Событие в чужом регионе:** × 0.3, а региональная программа для другого региона не засчитывается вовсе.
- **Курс не той валюты** (у компании юань, а новость про евро): × 0.3 к макровлиянию. Доллар так не считается: «рубль укрепился до 85 за доллар» — это общий курс рубля.

Ещё два правила про сущности:
- страна ВЭД засчитывается только для торговых, санкционных, регуляторных, валютных и корпоративных новостей: «сталь в Китае подешевела» — это цена, а не торговля с Китаем;
- для новости о курсе компания с ВЭД или валютными обязательствами получает прямую связь.
- **Нет никакой связи с компанией:** × 0.2.

После этого:
- **дубли** (одно событие у двух изданий, Jaccard ≥ 0.35) схлопываются в одну карточку;
- **порог** — 0.5, в ленту попадает до 5 карточек. Если порог не прошла ни одна, показываются две общие макроновости с пометкой в трейсе.

Роль (`roles.py`) умножает веса:
- факторов — финдиректору выше ставка и курс;
- типов событий — бухгалтеру выше правила, и его вес может быть больше 1;
- сущностей — бухгалтеру выше экспорт и взносы, закупкам — сырьё.

## Проверка качества отбора

```bash
python -m agent eval            # отчёт по случаям
python -m agent eval --json     # то же в JSON
```

Набор: `agent/eval/selection_set.json` — 13 случаев «компания × роль» по 24 моковым новостям. Свой набор новостей подключается полем `"news_file"`; у каждой новости должно быть поле `"extraction"` (разметка `EventExtraction`, например из прогона на модели), потому что `eval` работает без модели. Оценки: 2 — должна быть в ленте, 1 — уместна, отсутствие оценки — лишняя. Метрики:
- P@5 — доля уместных среди показанных;
- R@5 — доля обязательных, попавших в ленту;
- nDCG@5;
- число лишних карточек;
- число пар дублей.

Тест `test_quality_on_labeled_set` не пропускает правки весов, если P@5 или R@5 падают ниже 0.9.

| дата | P@5 | R@5 | nDCG@5 | лишних | что сделано |
|---|---|---|---|---|---|
| 23.10 исходно | 0.77 | 0.85 | 0.76 | 15 | только макро + отрасль + регион |
| 23.10 | 0.97 | 1.00 | 0.90 | 2 | сущности, близость, штрафы за чужую отрасль/регион/валюту, дубли, веса ролей |
| 23.10 вечер | 0.98 | 1.00 | 0.87 | 1 | макровлияние без потолка — по отчёту промпт-инженера; рознице без кредита ставка больше не попадает |
| 23.10 поздно | 0.97 | 1.00 | 0.89 | 2 | штраф за чужую отрасль для всех нешироких событий, страны только для торговли и расчётов, доллар = общий курс |

**Набор промпт-инженера** (`llm/eval/for_agent/`, 16 новостей × 6 компаний, разметка Gemma):

| дата | P@5 | R@5 | nDCG@5 | лишних | |
|---|---|---|---|---|---|
| 23.10 первый прогон | 0.86 | 0.88 | 0.91 | 7 | на тех новостях, которых отбор раньше не видел |
| 23.10 после правок | 0.96 | 0.96 | 0.96 | 2 | правила исправлены по трём найденным промахам |

```bash
python -m agent eval --set llm/eval/for_agent/prompt_selection_set.json
```

После правок этот набор уже нельзя считать незнакомым. Для критерия 05 в воскресенье нужен прогон на 5–10 свежих новостях, которых не видел никто.

**Предупреждение.** Разметку и моковые новости делала я, и веса подгонялись под тот же набор, так что цифры завышены. Честная проверка будет на тестовом наборе промпт-инженера (15–20 новостей × 5–6 профилей) после того, как его проверит аналитик. Его нужно добавить в тот же файл, в том же формате.

Оставшиеся промахи:
- курс евро попадает импортёру, у которого валюта не указана;
- спад розничной торговли попадает оптовику оборудования: карта ОКВЭД с двумя знаками не отличает 46.6 от 46.3.

## Открытые вопросы

1. **Источник новостей.** В бэкенде нет ни парсера, ни таблицы новостей. Когда появятся, в `agent_port.generate_insights` передаётся `news_provider(company_id, period) -> [dict]`. Неразмеченные новости агент размечает сам, до 20 за прогон.
2. **Компании из БД в API.** `GET /companies` пока отдаёт моки (`c-001`…). Агент уже умеет брать профиль из таблицы `companies`, но `refresh` для `U_…` вернёт 404, пока список компаний в API не переведён на БД.
3. **Ссылки на материалы банка.** В тезисах нет URL, а даты указаны с точностью до месяца (`published_at` = 1-е число). Нужны ссылки на 9 материалов от аналитика. Без них ссылка «к первоисточнику» для аналитики банка пустая.
4. **Публикация `replay_cache/`.** В записанных промптах есть строки компаний из данных кейса. Перед коммитом кэша проверить, можно ли выкладывать эти данные в публичный репозиторий. Если нельзя — сделать репозиторий приватным или передать кэш жюри отдельно.
5. ~~`llm.insight`~~ — сделано: агент передаёт свою проверку через `interpret(extra_check=...)`.
