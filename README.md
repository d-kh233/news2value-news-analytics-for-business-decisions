# News2Value — новостная аналитика для бизнес-решений

Команда News2Value, Альфа-Хакатон. Сервис внутри интернет-банка для бизнеса: из потока новостей
он выбирает то, что касается конкретной компании, и объясняет, что это для неё значит —
какие риски и возможности, что можно сделать и как событие оценивает Альфа-Банк.
У каждого утверждения в карточке видно, откуда оно: факт из новости, позиция банка или вывод модели.

> Черновик README на 24.10. Финальная версия с проверкой чистого запуска — 25.10.

## Как это работает

```
 новости ──► разметка события ──► отбор под компанию ──► аналитика банка ──► карточка ──► самопроверка ──► критик
            (Gemma: тип,          (отрасль, регион,       (20 тезисов ЦМИ,    (6 блоков,   (числа, ссылки,   (не хватает данных —
             факторы, отрасли)     сырьё, страны ВЭД,      с учётом ОКВЭД)     роль         цитаты банка;     повторный поиск
                                   роль читателя)                              читателя)    исправление или   и карточка заново)
                                                                                            откат на правила)
 профиль компании ─┘
 (данные банка: ОКВЭД, продукты, ВЭД, регион + ручной профиль)
```

1. Фронтенд вызывает `POST /companies/{id}/insights/refresh?role=cfo`.
2. Бэкенд в фоне запускает агента (`backend/app/ml_ports/agent_port.py` → `agent/`).
3. Агент выполняет шаги по схеме выше. Каждый шаг пишется в трейс: какой инструмент вызвали, с чем, что вернул, был ли откат.
4. Новые карточки заменяют прежние. Трейс доступен по `GET /jobs/{job_id}/run`.

Карточка — схема `llm/schemas.py` `Insight`, её блоки:
- 01 что произошло;
- 02 почему это важно именно вам;
- 03 последствия — риски и возможности;
- 04 что можно сделать;
- 05 как оценивает банк;
- 06 какие признаки компании использованы.

В API она лежит в поле `details` инсайта (`docs/api-contract.md`).

## Запуск

Нужны Docker, Python 3.12 + [uv](https://docs.astral.sh/uv/) и Node.js 20+. Сначала:

```bash
cp .env.example .env
```

### Только интерфейс, на моках

```bash
cd frontend && npm install && npm run dev        # http://localhost:5173
```

Бэкенд не нужен. Кнопка «Обновить анализ» показывает записанный вывод агента.

### API + агент без ключа модели

```bash
docker compose up --build                        # API на http://localhost:8000, документация /docs
```

`LLM_MODE=stub` (по умолчанию) — агент работает без модели, карточки собираются по шаблонам.
`LLM_MODE=replay` — ответы моделей берутся из `replay_cache/`, ключ не нужен. Это режим для жюри.

Без Docker, если база не нужна:
```bash
cd backend && uv run --frozen uvicorn app.main:app --port 8000
```

### На сервере

```bash
docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml up -d --build
./deploy/check.sh
```

Интерфейс и API работают на порту 80. Подробно — в `deploy/README.md`.

### Интерфейс с настоящим API

В `frontend/.env` поставьте `VITE_USE_MOCKS=false`, затем `npm run dev`. Vite перешлёт запросы `/api/...` на `http://127.0.0.1:8000`.

### Данные кейса

Положите `df_Uid_data_hack.csv`, `df_Fid_Uid_link_hack.csv` и `df_Uid_payment_hack.csv` в `data/raw/`. Затем:

```bash
docker compose exec api python scripts/load_csv.py       # загрузка в PostgreSQL с отчётом
python -m agent inspect-csv data/raw/df_Uid_data_hack.csv  # что из профиля увидит модель
```

### С моделью и запись кэша для жюри

1. В `.env` задайте `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODE=live`, `AGENT_TODAY=2026-10-22`, `LLM_USE_SMART=1`, `LLM_USE_CRITIC=1`.
2. Запишите все компании, которые есть в API (`c-001`, `c-002`, `c-003`), во всех шести ролях:
   ```bash
   python -m agent record-demo
   ```
   Это те же профили и параметры, с которыми агента вызывает бэкенд. Примерно 90 карточек; записанное повторно не оплачивается, прерванную запись можно просто запустить заново.
3. Проверьте, что кэш полный, — без ключа и без новых вызовов:
   ```bash
   LLM_MODE=replay python -m agent record-demo
   ```
   Должно быть «Кэш полный».
4. Закоммитьте `replay_cache/llm/`. На сервере — `LLM_MODE=replay` и те же `AGENT_TODAY`, `LLM_USE_SMART`, `LLM_USE_CRITIC` (для Render они уже в `render.yaml`). Другая дата или другая модель — другие запросы, и карточки пойдут по шаблонам.

Лимит команды — 500 ₽ в день, расход виден в `replay_cache/llm/usage-ДАТА.json`.

## Переменные окружения

Все переменные — в `.env.example` в корне. Ключ модели хранится только в `.env`, а этот файл в `.gitignore`.

| переменная | по умолчанию | что это |
|---|---|---|
| `DATABASE_URL`, `POSTGRES_*` | см. шаблон | PostgreSQL. Без базы API работает на моках |
| `CORS_ORIGINS` | localhost:3000, :5173 | адреса фронтенда |
| `LLM_BASE_URL`, `LLM_API_KEY` | — | OpenAI-совместимый API организаторов |
| `LLM_MODEL_FAST` / `_SMART` / `_RESEARCH` | Gemma / GLM / DeepSeek | id моделей из чата организаторов |
| `LLM_MODE` | `stub` | `stub` — без модели, `live` — с моделью и записью ответов, `replay` — только записанные ответы |
| `LLM_USE_SMART` | `0` | `1` — карточки пишет GLM вместо Gemma (для финальных прогонов) |
| `LLM_USE_CRITIC` | `1` | второй вызов модели проверяет карточку; при нехватке данных агент ищет ещё и пишет заново. `0` — без критика |
| `LLM_DAILY_BUDGET_RUB` | `500` | дневной лимит; после него агент переходит на шаблоны |
| `LLM_CACHE_DIR` | `replay_cache/llm` | куда пишутся ответы моделей |
| `LLM_JSON_MODE` | `1` | `0`, если API не поддерживает `response_format` |
| `AGENT_TODAY` | сегодня | «сегодняшняя» дата агента. Для replay — та же, что при записи |
| `TOP_K_NEWS`, `MIN_RELEVANCE` | `5`, `0.5` | сколько карточек в ленте и порог релевантности |
| `TEAM_MEMBER` | — | кто гоняет модель — пишется в лог расхода |
| `VITE_USE_MOCKS` (frontend/.env) | `true` | фронтенд на моках или на API. В сборке для сервера — всегда `false` |
| `WEB_PORT` | `80` | порт интерфейса на сервере (`deploy/`) |

## Что ещё не готово

- **Источник новостей.** Пока агент работает на выдуманных новостях `agent/data/mock_news.json` (с пометкой `[MOCK]`).
- **Компании из базы.** `GET /companies` отдаёт демо-компании из моков. Компании из `companies` в API пока не выбрать.
- **Ссылки на материалы банка.** У тезисов банка нет ссылок на первоисточник.
- **Площадка для деплоя.** Сборка готова (`deploy/`), площадку пока не выбрали.
