# Метрики качества и мониторинг AI-компонента

Черновик промпт-инженера, 24.10.2026. Для критериев 07 (масштабирование и сопровождение) и 08 (метрики и мониторинг качества с учётом обратной связи). Цифры — с прогонов на наших тестовых наборах; как их воспроизвести, сказано в каждом разделе.

## 1. Что измеряем

| Уровень | Вопрос | Где считается |
|---|---|---|
| Отбор | Попадают ли в ленту события, важные именно этой компании? | `python -m agent eval` |
| Интерпретация | Инсайт персональный, обоснованный, с позицией банка и без выдумок? | `python -m llm.eval_run --critic` |
| Надёжность | Что происходит на шуме, обрезанных текстах и неполном профиле? | `python -m llm.robustness` |
| Польза для пользователя | Считают ли руководители инсайты полезными? | оценка «полезно / бесполезно» и комментарий к инсайту в интерфейсе (API обратной связи бэкенда) |

Пример, который система обработала сама: новость «зарплаты разработчиков +20%» для IT-компании. Аналитика банка говорит об охлаждении роста зарплат в IT до 6%. Инсайт называет расхождение отдельным пунктом и советует перепроверить динамику перед бюджетированием, а не выдаёт одну из оценок за истину.

### Надёжность (ограничение 05 кейса)

| Сценарий | Ожидаемое поведение | Результат |
|---|---|---|
| Реклама | помечена как шум, инсайт не строится | ✓ |
| Обрезанный текст | флаг «текст обрезан», в пробелах названо, чего не хватает, уверенность не «высокая» | ✓ |
| Компания без ОКВЭД | инсайт есть, в пробелах «вид деятельности не указан» | ✓ |
| Пустой профиль | нет ссылок на несуществующие признаки, в пробелах «вывод общий, без персонализации», уверенность не «высокая» | ✓ |
| Новость противоречит аналитике банка | расхождение названо | ✓ |
| Ответ модели не по формату | модели показывают ошибку, она исправляет (за прогон: до 1 из 22 интерпретаций и 1–2 из 16 разметок); если не исправила — карточка по правилам без модели | ✓ |

## 3. Как устроен контроль качества внутри одного инсайта

1. **Автоматические проверки** (код, без модели): ссылки только на переданные источники; каждое «почему важно» связано с признаком компании; позиция банка — только со ссылкой на материал банка; в фактах нет чисел, которых нет в новости. Ошибка → модель получает текст ошибки и исправляет ответ.
2. **Критик** (второй вызов модели): оценивает по пяти критериям и ищет пересказ, общие фразы, вывод модели под видом позиции банка, незамеченное расхождение новости с аналитикой. Существенная проблема → одна доработка с замечаниями. Не хватает данных → критик возвращает агенту шаги дополнительного поиска (встраивается в оркестратор).
3. **Трассировка**: в карточке сохраняются версия промпта, использованные признаки компании и источники; в трассировке запуска — результаты проверок и вердикт критика.

## 4. Мониторинг в эксплуатации

**Перед каждым изменением промптов, карты отраслей или весов отбора** — регрессионный прогон (несколько минут; расход виден в логе шлюза):
`unittest` → `agent eval` → `llm.eval_run --critic` → `llm.robustness`. Изменение выпускается, если ни одна метрика не просела больше чем на 5 п.п. Версия промпта (`PROMPT_VERSION`) меняется при каждой правке, по ней сбрасывается кэш ответов.

**В работе — автоматически, по логам и обратной связи** (пороги — предлагаемые, уточняются по первым неделям работы):

| Сигнал | Что значит | Порог для разбора |
|---|---|---|
| Доля «бесполезно» в оценках пользователей | падает ценность | > 30% за неделю |
| Причина «нерелевантно»* | ошибается отбор → веса, карта отраслей | рост в 2 раза |
| Причина «неточно»* | ошибается интерпретация → промпт, критик | любой случай разбирается вручную |
| Причина «непонятно»* | формат и язык → промпт | > 10% |
| Доля доработок критиком | модель или новости поменялись | > 40% |
| Доля инсайтов без позиции банка | устарела или не покрыта аналитика банка | > 20% → запрос аналитикам на новые тезисы |
| Доля ответов не по формату | сбой модели или шлюза | > 5% |
| Расход бюджета на модели | рост стоимости | лог шлюза, дневной лимит |

\* Причину оценки сейчас можно написать в комментарии; выбор причины из списка — следующий шаг для интерфейса.

Разрезы для всех метрик: отрасль (ОКВЭД), роль пользователя, тип события, версия промпта.

**Экспертная проверка** — раз в неделю аналитики банка размечают 30 случайных инсайтов по шести вопросам кейса (что произошло, почему важно, последствия, действия, позиция банка, на чём основан вывод). Их оценки сравниваются с оценками критика: если расходятся, правится промпт критика. Размеченные случаи пополняют тестовый набор.

**Как обратная связь превращается в улучшения:**
- «нерелевантно» → разметка случая в тестовый набор отбора → правка весов или карты отраслей → регрессия;
- «неточно» → разбор трассировки (какой источник, какой признак, что сказал критик) → правка промпта или проверки;
- новые темы без позиции банка → запрос аналитикам → новые тезисы с отраслью и факторами.

## 5. Масштабирование (критерий 07)

- **Новые отрасли** — карта «ОКВЭД → чувствительность к 10 факторам» (88 разделов) правится как таблица, без кода. Для более детальных кодов есть скрипт, который строит черновик моделью и показывает аналитику только расхождения.
- **Новые источники новостей** — любой источник приводится к общему формату разметки (тип события, факторы, отрасли, страны), дальше конвейер тот же.
- **Новые материалы банка** — тезис с указанием факторов и отраслей добавляется в базу и сразу участвует в поиске.
- **Новые роли и типы клиентов** — словарь ролей (акценты для модели и веса отбора) расширяется без изменения конвейера.
- **Модели** — задаются переменными окружения; дешёвая модель на разметку, модель посильнее на интерпретацию и критика.

## 6. Ограничения текущих цифр

- Набор небольшой (16 новостей, 6 компаний) и синтетический; разметку делала команда, а не независимые эксперты.
